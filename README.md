# Автоодобрение заявок и антикраш для Discord

Бот проверяет встроенные заявки **Apply to Join** каждые две секунды и одобряет все отправленные заявки на сервере из `DISCORD_GUILD_ID`. Антикраш настраивается отдельно для каждого сервера. Новый сервер начинает в режиме `off`.

## Запуск

1. В Discord Developer Portal создай приложение с ботом. Включи **Server Members Intent** во вкладке **Bot**, чтобы бот мог проверять участников, доверенные роли и повторные входы.
2. Установи приложение на сервер со scope **bot** и **applications.commands**. Для заявок включи **Apply to Join** и дай боту **Kick Members**. Для антикраша дай **View Audit Log** и **Manage Roles**, а в рабочих голосовых каналах также **Connect** и **Move Members**. Боту нужен **View Channel** в проверяемых каналах, **Send Messages** и **Embed Links** в канале логов, если включена отправка уведомлений и доступ на чтение и отправку сообщений в канале связи, если он задан.
3. Заведи `DISCORD_BOT_TOKEN` как секрет и `DISCORD_GUILD_ID` как переменную окружения. При локальном запуске скопируй `.env.example` в `.env`. Если антикраш не нужен, `ANTICRASH_ENABLED=false` оставляет только автопринятие заявок.

Требуется Node.js 22.13+ из ветки 22 LTS или Node.js 24+. Для локального запуска:

```sh
npm ci
node --env-file=.env bot.mjs --check
node --env-file=.env bot.mjs
```

`--check` проверяет чтение очереди заявки, основной запуск включает автопринятие и регистрирует команды. На хостинге с уже заданными переменными окружения команда запуска — `npm start`.

### Bothost

Укажи публичный GitHub-репозиторий и ветку `main`. В дополнительных настройках включи **Использовать собственный Dockerfile** (в форме выбора стека также есть **Dockerfile**). Сборка должна начинаться с `FROM node:22-alpine`. `DISCORD_BOT_TOKEN` и `DISCORD_GUILD_ID` вводятся в панели Bothost. База по умолчанию сохраняется в `/app/data/anticrash.sqlite`. Затем запусти повторный деплой. [Настройка Dockerfile на Bothost](https://bothost.ru/docs/custom-dockerfile)

### Docker на своём сервере

```sh
docker build -t discord-auto-approve .
docker run -d --restart unless-stopped --env-file .env \
  -e ANTICRASH_DB_PATH=/app/data/anticrash.sqlite \
  -v discord-auto-approve-data:/app/data --name discord-auto-approve discord-auto-approve
docker logs -f discord-auto-approve
```

Запускай один экземпляр бота. База создаётся при первом запуске. Путь берётся из `ANTICRASH_DB_PATH`, затем `DATA_DIR`, затем `./data/anticrash.sqlite`. Храни её на постоянном диске. SQLite сохраняет инциденты, исходные снимки, подтверждения, операции и очередь доставки. Ошибки Discord HTTP 401 указывают на токен, 403 — на доступ или права.

## Роль при входе

Укажи ID роли в `DISCORD_JOIN_ROLE_ID`. Бот выдаёт её новым участникам на сервере из `DISCORD_GUILD_ID`, в том числе после одобрения заявки. Если включена проверка правил, роль выдаётся после завершения проверки Discord. Роль должна находиться ниже роли бота. Для выдачи нужно **Manage Roles**. При действующем карантине выдача откладывается.

## Настройка антикраша

1. Создай обычную роль без опасных прав и размести её ниже самой высокой роли бота. Роль бота также должна быть выше ролей, которые он должен иметь возможность снять.
2. Владелец запускает `/anticrash setup` и выбирает канал логов и роль карантина. Можно указать отдельный текстовый канал связи со стаффом и роль для критических оповещений. Мастер проверяет Audit Log, иерархию, разрешения и каналы. При блокере он сохраняет режим наблюдения и выводит детали.
3. Проверь `/anticrash status` и `/anticrash rules`. Настрой каждое событие через `/anticrash rule`, включая личный порог, окно в секундах, общий порог и реакцию `log`, `alert` или `quarantine`. Общий порог по нескольким исполнителям поднимает тревогу. Личный порог проверяется независимо.
4. При необходимости выдай права управления командой `/anticrash manager`. Только владелец может назначать администраторов. Доверенные записи используют `/anticrash trust-set`, `trust-list`, `trust-remove`. `allow` разрешает перечисленные действия, `limit` задаёт повышенный порог, `immune` явно даёт полный иммунитет.
5. Для доверенной роли проверь держателей и подтверди их через `/anticrash trust-confirm`. Новое членство в роли требует подтверждённой выдачи владельцем или уполномоченным администратором. После редактирования роли доверие к её держателям нужно подтвердить заново. При переходе через `off` подтверждения также нужно обновить.
6. По результатам наблюдения включи `/anticrash mode value:active`. В наблюдении инциденты фиксируются с ожидаемой реакцией. Автоматический и ручной карантин требуют активного режима. Явно подтверждённое снятие ранее наложенного карантина доступно в любом режиме.

Примеры настроек:

- `/anticrash rule event:channel-delete limit:3 seconds:15 global:5 reaction:quarantine`
- `/anticrash rule event:dangerous-role limit:1 seconds:15 reaction:quarantine`
- `/anticrash trust-set kind:user id:123456789012345678 mode:limit events:ban limit:12 minutes:60 comment:дежурная_смена`

Неподтверждённый исполнитель или объект, неоднозначное сопоставление и неподтверждённая иерархия дают тревогу. Некоторые перестановки Discord пишет одной агрегированной записью без ID ролей. Порог для таких записей не применяется к конкретному участнику без подтверждения действий. Записи старше двух минут анализируются для журнала, без автоматических санкций.

## Карантин и восстановление

- `/anticrash quarantine` — ручное помещение с причиной. `/anticrash quarantines` показывает статус, `/anticrash retry` повторяет прерванный или частичный карантин. При повторном входе и после перезапуска работа возобновляется из SQLite.
- Бот сохраняет исходные роли и персональные переопределения. Он снимает доступные опасные роли, назначает роль карантина, ограничивает рабочие каналы персональными переопределениями и отключает от рабочего голосового канала при наличии разрешений. Полный статус появляется только после проверки фактического доступа. Для неподконтрольных ролей, оставшихся разрешений и технических ошибок есть частичный статус с деталями.
- `/anticrash release` показывает предварительный список и код на пять минут. `/anticrash release-confirm` запускает восстановление. Для возврата перечисленных опасных ролей отдельно укажи `dangerous:True`. Если права или роль изменились после снимка либо предпросмотра, проверка пропускает конфликтующую операцию и сообщает об этом.
- `/anticrash incidents`, `/anticrash incident` и `/anticrash logs` доступны и при сбое доставки в Discord. Время в журнале хранится в UTC и отображается в часовом поясе Discord. По умолчанию автоматические сообщения в Discord выключены. Журнал сохраняется в SQLite и доступен через приватную команду `/anticrash logs`. Для отправки уведомлений в канал журнала укажи `DISCORD_LOG_MESSAGES=true`.
- Роль карантина и канал связи фиксируются для открытого карантина. Если их удалили, сними оставшиеся изменения через предварительный просмотр или исправь состояние вручную. Управляемые роли, роль владельца и роли выше или на уровне бота недоступны для снятия. **Administrator** обходит канальные ограничения. Антикраш не банит, не кикает и не пересоздаёт удалённые объекты.

## Проверки

```sh
npm ci
npm test
```

Тесты используют имитацию Discord API и временную SQLite. В них проверяются автопринятие, повтор после HTTP 429, режим наблюдения, доверие, задержка и дубли Audit Log, общие пороги, конфликтующие права, частичный карантин, подтверждённое снятие и восстановление после перезапуска.
